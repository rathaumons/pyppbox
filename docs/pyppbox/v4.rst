V4 upgrade guide
================

**V4 development** is on ``dev``. The package version remains **3.15.0** until
release. This checkout adds RF-DETR, ArcFace/AdaFace, and performance/stability
improvements while retaining the existing config formats. See
:doc:`../releasenotes` for the complete implemented changes.

Existing projects and configurations
----------------------------------------

Existing YAML/JSON files, dictionary inputs, module names, path rules, Person
attributes, and public facades remain supported. There is no config schema
migration. Old config directories gain RF-DETR and ArcFace/AdaFace defaults in memory without being
rewritten. GUI saves retain supported extension fields and other module documents.
Validation now diagnoses invalid values or missing selected assets before model
initialization. A grouped config save supports rollback and explicit recovery;
use one writer and pause readers during that operation.

The default YOLO dependency is ``pyppbox-ultralytics>=8.4.144`` and still imports
as ``ultralytics``. Follow :doc:`../getstarted` when replacing the earlier fork.
Core metadata/CI covers Python 3.9–3.13. The optional RF-DETR runtime needs
Python 3.10+ and ``rfdetr>=1.10.0,<1.11.0``.

GUI configuration and devices
------------------------------

All module popups share aligned input/path rows and a centered, separated Save
button. RF-DETR, YOLO Ultralytics, Torchreid, ArcFace, and AdaFace use editable
device dropdowns with backend-specific presets and validation. YOLO Classic,
FaceNet, and DeepSORT show a final read-only ``device`` row before Save, with
``auto by OpenCV`` or ``auto by TensorFlow`` in the value column.
Device defaults and configuration keys are unchanged. In particular, RF-DETR's
``auto`` differs from YOLO's empty/``None`` automatic setting, and FaceNet's
``gpu_mem`` remains a memory limit. See :ref:`device-selection` for the full
reference. The launcher link also stays readable across light/dark theme changes.

RF-DETR and model data
--------------------------

RF-DETR is an optional V4 detector supporting Nano, Small, Medium, and current
Large detection checkpoints.
Install ``requirements/rfdetr.txt`` with ``python -m pip install -r`` from the
repository root, separately from the optional data wheel. All eight module
data wheels use the `v1.6.0 release
<https://github.com/rathaumons/pyppbox-data/releases/tag/v1.6.0>`_, including
``pyppbox-data-rfdetr``, ``pyppbox-data-arcface``, and ``pyppbox-data-adaface``; GTA V data
keeps its independent version. See :doc:`../getstarted` for installation commands.

After installing the requirements, select ``RF_DETR`` in the GUI or with
``setMainDetector('RF_DETR')``. Like YOLO, the bundled config uses GPU
``device: 0`` and the local model path
``data/modules/rf_detr/rf-detr-nano.pth`` under the installed pyppbox package.
Set ``device: cpu`` for CPU inference. The ``pyppbox-data-rfdetr`` wheel populates
the standard paths. You can also browse to a downloaded checkpoint, or set
``model_file: ''`` to use RF-DETR's automatic download/cache. Existing
configurations work without migration.

**RF-DETR weights:**
`Nano <https://storage.googleapis.com/rfdetr/nano_coco/checkpoint_best_regular.pth>`_,
`Small <https://storage.googleapis.com/rfdetr/small_coco/checkpoint_best_regular.pth>`_,
`Medium <https://storage.googleapis.com/rfdetr/medium_coco/checkpoint_best_regular.pth>`_,
and `Large <https://storage.googleapis.com/rfdetr/rf-detr-large-2026.pth>`_.
Nano/Small/Medium downloads have the same server filename; save them separately
as ``rf-detr-nano.pth``, ``rf-detr-small.pth``, and ``rf-detr-medium.pth``.
Keep Large as ``rf-detr-large-2026.pth``. :doc:`../examples/example_15` lists
filenames, destinations, offline setup, and custom class IDs. Roboflow's
`pretrained aliases <https://docs.roboflow.com/models/pretrained-aliases#rf-detr>`_
describe its Inference service; pyppbox loads these local PyTorch checkpoints
through ``rfdetr``.

ArcFace, AdaFace, and identity classifiers
------------------------------------------

ArcFace and AdaFace are optional V4 reiders; earlier releases do not include
these adapters. Install ``requirements/faces.txt`` using ``python -m pip install -r`` from the
repository root and either v1.6.0 face data wheel. For NVIDIA GPU inference,
use ``requirements/faces_gpu.txt`` with compatible CUDA/cuDNN libraries. Each wheel
contains its own SCRFD detector, embedding model, and GTA V identity classifier.
Select ``ArcFace`` or ``AdaFace`` in the GUI, or use ``setMainReIDer('ArcFace')``
or ``setMainReIDer('AdaFace')`` to load the bundled paths. Both default to CPU;
CUDA requires a compatible ONNX Runtime GPU build.
The existing FaceNet and Torchreid interfaces are retained. See
:doc:`modules/reiders` for direct inference, training, CUDA configuration, model
terms, and thresholds.

Pipeline ownership and cleanup
------------------------------

Create one ``MT`` per independent stream and use its context manager or ``close()``
to release owned models and sessions. ``reset()`` clears stream state while
retaining loaded models. Stage replacement prepares candidates before publication,
so failed initialization retains the active pipeline. Replacement can temporarily
hold old and new models together. Calls on one pipeline are not synchronized;
use independent instances for independent streams. The shared facade remains
available for a single stream. See :doc:`standalone` for examples and failure rules.

GUI launcher/demo processes now own their workers and clean up on completion,
interruption, and unexpected parent loss. Logs and GUI handoffs live in writable
user/session directories rather than the installation. ``PYPPBOX_RUNTIME_DIR``
overrides that location. Root application logging is left unchanged. Configuration
edits and explicit model/result paths retain their existing destinations; use a
writable custom config directory if the installation is read-only. Abrupt process
death may leave a session folder even though its process tree stops. See
:doc:`utils` for logging switches and platform paths.

Performance and correctness
---------------------------

The implementation removes full-frame ReID copies, indexes GT/DeepSORT metadata,
avoids accumulated result-list copies, consolidates YOLO result conversion, and
defers runtime imports. Torchreid inference batching is bounded and opt-in through
``reidPeople(batch_size=...)``; scalar processing stays the default. Large CPU
batches can be slower, and confidence values can differ slightly. See
:doc:`standalone` before enabling batches for your models.

Invalid or invisible ReID crops are skipped. DeepSORT retains actual post-NMS
detection associations; corrected identity assignments can differ from the old
buggy behavior. Result recording rejects out-of-order or misaligned frames before
writing. ResIO still retains recorded snapshots, so its memory use grows with the
recording duration.

Validation includes 27 core source/installed-wheel compatibility jobs and six
CPU model/GUI jobs on Linux, Windows, and macOS. The initial YOLO/SORT/Torchreid
replays preserve outputs, identities, and ReID counts. RF-DETR's four variants,
offline loading, failure recovery, repeated replacement, independent streams,
generated native/Lightning custom heads, and GUI descendant cleanup also pass.
Those custom fixtures validate formats and class mapping, not trained-model
quality. This bounded coverage does not certify every downstream model or scene.

The existing **Test Core Linux**, **Test Core Windows**, and **Test Core macOS**
workflows run source/installed-wheel compatibility checks on pushes and pull
requests. Their backend example checks run when started manually. The manual
**Test CPU Pipeline Comparison** workflow groups the YOLO/SORT/Torchreid and
RF-DETR comparisons as separate jobs across all three systems, retaining the
captured baselines, pinned dependencies, GUI checks, and result artifacts.

Measured CPU performance varies by workload and platform; no universal speedup or
15% end-to-end gain is claimed. Additional GPU qualification and an eight-hour soak
are not release requirements. Select detectors and batch limits using your own
representative videos and hardware.
