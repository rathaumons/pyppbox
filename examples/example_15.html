15. RF-DETR detection and tracking#

RF_DETR is an optional detector included in pyppbox V4, using the existing configuration files, public pipeline, and GUI. Python 3.10+ is required for RF-DETR; existing detectors remain usable without installing this extra.

Install into a virtual environment from this checkout:

python -m pip install ".[rfdetr]"

For a release package that includes RF-DETR, use python -m pip install "pyppbox[rfdetr]". Earlier published versions do not provide this extra.

Run from the repository root, using its bundled video:

python -m examples.example_15_rfdetr --device cpu --frames 30

Use --device cuda:0 for a compatible CUDA PyTorch installation. Add --show for an annotated video window, or --video path/to/video.mp4 for another clip. The example uses SORT tracking and disables ReID, so no ReID model files are needed.

Model and config choices#

The adapter targets rfdetr>=1.10.0,<1.11.0 and provides the Apache-designated Nano, Small, Medium, and Large detection models from RF-DETR. Each model uses its published native resolution. Segmentation, keypoint-preview, Plus models, training, ONNX, and TensorRT export are outside this initial integration.

The existing detectors.yaml format accepts this additional document:

dt_name: RF_DETR
conf: 0.4
model_size: nano
device: 0
max_det: 100
model_file: data/modules/rf_detr/rf-detr-nano.pth
person_class_id: 1
optimize: True
repspoint_calibration: 0.25

Like the YOLO defaults, the bundled config selects GPU device: 0 and a local checkpoint under data/modules. Place the Nano weights at {pyppbox root}/data/modules/rf_detr/rf-detr-nano.pth for internal configs, or select your downloaded checkpoint using the GUI. Set device: cpu when CUDA is unavailable. Integer GPU indices are saved as integers and passed to RF-DETR as cuda:N.

A nonempty model_file must be an existing local checkpoint matching model_size. Paths follow the existing pyppbox rules: package-relative for internal configs, working-directory-relative for custom configs or mappings. When a mapping omits model_file, its local default filename follows model_size. The GUI also updates a standard default path when switching sizes; a custom checkpoint path is retained. Model loading is deferred until selection.

The first three URLs all end in checkpoint_best_regular.pth; rename each download to the corresponding filename above. For example, download Nano into your working directory with:

curl -L --fail -o rf-detr-nano.pth https://storage.googleapis.com/rfdetr/nano_coco/checkpoint_best_regular.pth

Browse to the file in the RF-DETR settings panel and select its matching size. Alternatively, the optional pyppbox-data-rfdetr v1.5.0 wheel installs all four checkpoints under {pyppbox root}/data/modules/rf_detr/, matching the existing internal config paths. See 🚀 Getting Started for the six v1.5.0 data-wheel installation commands and download checksum files. Installing a data wheel does not install the RF-DETR runtime; install .[rfdetr] from the source checkout too.

The data wheel removes optimizer, scheduler, and epoch state from Nano/Small/Medium, keeping every model tensor and the architecture/class metadata unchanged. Large’s published checkpoint is already weights-only. The smaller files produce the same inference outputs; this does not change steady-state inference compute. Their packaged hashes differ from the direct upstream downloads and are recorded separately with the source hashes in WEIGHTS.json. RF-DETR 1.10 may log an original-download MD5 warning for these local files; it still loads them without replacing them. They cannot resume the original optimizer/scheduler state.

For offline use, install the runtime dependencies and data wheel in advance, or select an existing local checkpoint. These four complete checkpoints were tested with Python network access blocked. Custom model architectures may have additional assets to prepare separately. Never select a generated CI fixture as a production model.

Roboflow’s pretrained aliases include more models for its Inference service. Those service model IDs are not checkpoint paths for this adapter; xlarge, 2xlarge, segmentation, and keypoint-preview models are not exposed here.

Automatic downloading and cache#

An explicitly empty model_file: '' lets RF-DETR download its pretrained checkpoint on first use instead. Set RF_HOME to choose its cache directory.

With the supported RF-DETR 1.10 release, the default cache is ~/.roboflow/models (on Windows, under your user profile). Nano, Small, Medium, and Large use rf-detr-nano.pth, rf-detr-small.pth, rf-detr-medium.pth, and rf-detr-large-2026.pth, respectively. Keep model_file empty when switching model sizes to select the matching pretrained checkpoint automatically. For a local checkpoint, use the GUI’s browse button and select its matching model_size.

person_class_id is 1 for RF-DETR’s pretrained COCO models. Fine-tuned models can use a different ID (often 0); set it explicitly for your checkpoint. General MyRFDETR.detect() class filters also use native RF-DETR IDs.

The wrapper accepts BGR uint8 frames, converts them to RGB for RF-DETR, and returns the same BGR array. Output is the existing Person box representation, with confidence in [0, 1] and empty keypoints. Boxes are clipped to the image; class and width filters run before the confidence-ordered max_det limit. No extra NMS or IoU parameter is added to RF-DETR’s native predictions.

optimize=True calls RF-DETR’s inference preparation once, in place, with compilation disabled. This avoids keeping a second model copy. The wrapped model is then for inference only; use a separate RF-DETR instance for training/export.

Old configuration directories require no migration: RF-DETR defaults are available in memory when its document is absent. Selecting it by name or opening the GUI uses those defaults; saving the RF-DETR dialog adds its document. Existing detector dialogs preserve the other detector documents when saving.

Example source#

# Copyright (c) 2026 UMONS-Numediart | AGPL-3.0 License
"""Optional RF-DETR detection and SORT tracking; see the --help options."""
import argparse
from pathlib import Path

import cv2

from pyppbox.ppb.mt import MT
from pyppbox.utils.visualizetools import visualizePeople


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('--video', default=str(Path(__file__).parent / 'data/gta.mp4'))
    parser.add_argument('--model-size', choices=['nano', 'small', 'medium', 'large'], default='nano')
    parser.add_argument('--checkpoint', default='', help='Optional local checkpoint matching --model-size.')
    parser.add_argument('--person-class-id', type=int, default=1, help='COCO person ID is 1; custom models may use 0.')
    parser.add_argument('--device', default='cpu', help='cpu, cuda:0, mps, or auto')
    parser.add_argument('--frames', type=int, default=30)
    parser.add_argument('--show', action='store_true', help='Display annotated frames in an OpenCV window.')
    args = parser.parse_args()
    if args.frames < 1:
        parser.error('--frames must be positive')
    capture = cv2.VideoCapture(args.video)
    try:
        if not capture.isOpened():
            raise FileNotFoundError(f'Cannot open video: {args.video}')
        pipeline = MT()
        pipeline.setMainDetector(dict(dt_name='RF_DETR', model_size=args.model_size,
                                      model_file=args.checkpoint, person_class_id=args.person_class_id,
                                      device=args.device, conf=.4))
        pipeline.setMainTracker('SORT')
        pipeline.setMainReIDer('None')
        for index in range(args.frames):
            ok, frame = capture.read()
            if not ok:
                break
            people, _ = pipeline.detectPeople(frame, img_is_mat=True)
            people = pipeline.trackPeople(frame, people, img_is_mat=True)
            print(f'Frame {index}: {len(people)} people; track IDs {[person.cid for person in people]}')
            if args.show:
                cv2.imshow('RF-DETR + SORT', visualizePeople(frame, people))
                if cv2.waitKey(1) & 0xFF == ord('q'):
                    break
    finally:
        capture.release()
        if args.show:
            cv2.destroyAllWindows()


if __name__ == '__main__':
    main()

Validation#

The core suite exercises the adapter, configuration fallback, and pipeline with deterministic model boundaries, without downloading RF-DETR:

python -m unittest discover -s tests -v

For the offscreen RF-DETR settings dialog, with PyQt6 installed:

python -m unittest discover -s tests/integration -p test_rfdetr_gui.py -v

For real CPU/CUDA inference, install the RF-DETR extra and set PYPPBOX_RUN_RFDETR=1 before running:

python -m unittest discover -s tests/integration -p test_rfdetr_model.py -v

The opt-in test downloads/caches Nano weights if absent and uses the bundled GTA video. CUDA is tested when available. Published upstream TensorRT benchmarks do not establish the performance of this PyTorch adapter; compare complete pipelines on representative clips before selecting a detector.

The dedicated CPU workflow validates all four variants on Linux x86_64, Windows AMD64, and macOS ARM with Python 3.11, RF-DETR 1.10.0, and Torch 2.5.1. It compares native/prepared predictions and frozen/current pyppbox wheels, including class filters, SORT gaps/recovery, rendered output, offline loading, missing/corrupt checkpoints, unavailable devices, reset/close, and independent streams. Generated two-class native and Lightning checkpoints exercise class-head loading and numeric class IDs; they do not establish trained-model accuracy or support every custom architecture. GUI process cleanup is tested with actual owned subprocess trees on all three systems. Earlier Nano CUDA checks remain separate from CPU qualification.
